### 1.3 术语

| 术语 | 含义 |
|---|---|
| 步骤（Step） | 旅程 10 幕之一（transit → boarding），数据定义在 data/steps.js |
| 分支（Branch） | 一个步骤内的可选路径（如值机三选一）；不同分支产生不同 3D 动作与系统链路 |
| 链路（Flow） | 一次步骤+分支解析出的「系统节点 + 报文边」序列，渲染在底部链路条 |
| 知识窗（Info Window） | 点击术语/系统/报文/管理域弹出的浮动解释窗，全局单例 |
| 浮窗（Panel） | 可拖动/最小化/关闭/缩放的功能窗口，共 7 个 + 知识窗 |
| actor 分区 | 窗口按主体配色：旅客流程(青)/机场流程(金)/航司系统(蓝)/混合链路(渐变) |
| 悬浮球（FAB） | 可拖动控制球：单击=下一步，长按/双击=控制菜单 |
| 默认路径 | 每个分支点的预设选择，自动播放按它走完全程 |
| 版本戳 | gen-importmap.mjs 把全部本地 ES 模块 URL 加 ?v=版本，对抗 CDN 缓存 |
| A-CDM / AODB / DCS / BSM 等 | 民航业务术语，见产品内术语库（data/glossary.js，53 词条）|

## 2. 产品概述

### 2.1 产品定位

面向民航从业新人、数字化产品/技术人员与高校学生的**交互式教学模拟器**。核心命题：旅客看得见的旅程只是表象，每一步背后是多主体的系统与报文协同。三块同屏画面回答三个问题：物理世界发生了什么（3D）、数字世界发生了什么（链路条）、这一步归谁管（管理域地图）。

核心场景：
- 新员工/学生自学：按步推进 + 点击术语深挖
- 内训演示：自动播放按默认路径走完全程
- 数字化从业者查阅：99 个系统节点的厂商/部署/ICT 需求评估（按年旅客量 500 万人次为测算单位）

### 2.2 目标用户与典型场景

| 用户 | 场景 | 主要入口 |
|---|---|---|
| 机场/航司新员工 | 建立全流程与主体边界心智模型 | 逐步推进 + 分支对比 |
| 民航 IT 产品/开发 | 查系统接口、报文语义、ICT 量级 | 术语链接 + 管理节点全景 |
| 高校交通/航空专业 | 课本概念对应到具体触点 | 管理域地图 + A-CDM 里程碑 |
| 内训讲师 | 投屏演示 | 自动播放 + 管理者视角 |
| 离线/内网环境学员 | 无外网教室 | Electron 桌面版（完全离线）|

### 2.3 设计约束与原则

| 编号 | 约束 | 由来 |
|---|---|---|
| C-1 | 纯前端零后端：全部知识数据以 ES Module 字典硬编码，无任何 API 依赖 | 可静态托管、可离线打包 |
| C-2 | Three.js 必须 importmap + ES Module（r0.169 锁版），禁用已删除的 examples/js 旧路径 | r149 后旧路径 404 → 白屏（站点级规范）|
| C-3 | 全程序化建模，零外部 3D 资产（无 GLTF/贴图文件） | 首屏体积可控、离线打包简单 |
| C-4 | UI 词条不硬编码中文：全部走 t()/T() 双语字典，共享站点 opcstudio_lang | 站点级 i18n 规范；每次发布必须交付完整 EN 版 |
| C-5 | 所有信息面板必须是可拖动/最小化/关闭/缩放的浮窗；流程控制常驻不可关 | 用户明确要求（站点级 UI 规范）|
| C-6 | 发版必须先跑版本戳脚本再上传 | Cloudflare 区域强制 4h 浏览器 TTL 覆盖源站 no-cache，忘跑=线上新旧混装 |
| C-7 | 教学文案以 docs/ 洞察报告为唯一事实来源，不得新编术语口径 | 内容可信度 |
| C-8 | 桌面版零 Node 能力（contextIsolation+sandbox+nodeIntegration:false），页面 http(s) 链接一律转系统浏览器 | 安全基线 |
| C-9 | 左右对称几何分别建模，禁用 scale.x=-1 镜像 | 法线翻转导致光照错误（实测坑）|

## 3. 系统架构

### 3.1 分层与角色

四层单页应用（29 个 ES Module，约 6,000 行）：

| 层 | 目录 | 职责 | 关键文件 |
|---|---|---|---|
| 数据层 | data/（9 文件 2,718 行） | 纯字典零逻辑：旅程/系统/报文/管理域/术语/ICT/词条 | steps.js 666 行、ict.js 437 行、systems-more.js 388 行 |
| 逻辑层 | engine/（242 行） | 状态机+事件总线；链路解析 | state.js、flow-engine.js |
| 3D 层 | scene/（1,482 行） | 渲染器/世界/导演/道具/角色/补间/标注 | world.js 460 行、director.js 371 行 |
| DOM 层 | ui/（889 行） | 浮窗管理器 + 7 类窗口 + 术语链接 | window-manager.js、info-window.js |
| 总线 | main.js（233 行） | 把四层接起来；步骤驱动/自动播放/i18n 应用 | — |

### 3.2 数据流

单向驱动：用户操作 → engine/state（emit step/branch/toggle/finish）→ main.js playCurrent() → 并行更新 3D（director.enter + journeyPath + labels）与 DOM（rail/domains/flowbar/narrative 重渲染）。链路条内容 = flow-engine.resolveFlow(步骤, 分支, {oneId}) 纯函数解析，One ID 开关会在链路中插入生物识别节点。

### 3.3 安全模型

- Web 版：纯静态无用户数据；localStorage 仅存 3 个键（语言/悬浮球位置/默认路径），全部 try/catch 包裹，失败静默降级。
- 桌面版：Electron 43，渲染进程 sandbox + contextIsolation，无 preload、无 IPC；will-navigate/setWindowOpenHandler 拦截所有 http(s) 外链转系统浏览器；仅加载本地 app/ 文件。
- 服务端：静态托管（nginx + Cloudflare），无动态接口。

## 8. 服务端与部署

### 8.1 运行形态

静态文件托管：oracle-vm:/home/ubuntu/website/pax-journey/（nginx 8080 回源，Cloudflare 前置）。桌面安装包在同目录 downloads/ 下（三件 + 双语下载页）。无进程、无数据库。

### 8.2 发布流水线（真实步骤与坑）

- 盖版本戳：node scripts/gen-importmap.mjs <版本>。**坑：Cloudflare 区域设置强制 4 小时浏览器 TTL，覆盖源站 no-cache——忘盖戳则线上继续跑旧模块（2026-08-01 实测：文件已上传、页面仍旧版）。**
- 上传：rsync -az --partial（目录整传，勿把 data/x.js 单文件传到目录根——会拍平成错误路径且不报错，2026-08-01 踩过）。
- 验证：一律带 cache-bust 查询串 curl；大文件上传后必须回读服务器 sha256（**坑：macOS 自带 rsync 2.6.9 遇 --info=progress2 打 usage 退出，管道尾部又吞退出码，exit 0 不可信**；到 oracle-vm 的长连接约 4 分钟会被对端重置，需 --partial 续传）。
- 桌面版发布：desktop/ 下 npm run prep → smoke → dist，node scripts/gen-downloads-page.mjs <版本> 重建下载页后同步 downloads/。

## 10. 质量保障与已知问题

### 10.1 质量手段（实际在用）

- 浏览器实测流程：本地 devserver → 无头验证（__pax.pump 对抗 rAF 节流；CSS transition 同理需 getAnimations().finish() 后读值）→ 截图确认 → 线上 cache-bust 复验。
- 布局验收标准：五默认窗 getBoundingClientRect 两两求交，1600/1366/1120×800 三档 overlaps 必须为空（v0.9 起）。
- 桌面版门禁：--smoke 零页面错误才出包；产物再冒烟一次。
- EN 完整性抽查：切 EN 扫 CJK 残留。

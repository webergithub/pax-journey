## 1. 分析方法

**Gap = 目标能力（规划 PR）− 现状能力（规格 FR + 代码事实）。**

五元组：每条 Gap = 现状（带证据）/ 目标（引 PR）/ 差距陈述 / 级别 / 关闭验收（破坏性）。

**关闭纪律：Gap 只在其破坏性验收通过后关闭，代码合入不算。**

| 级别 | 含义 | 判据 |
|---|---|---|
| L1 品类硬伤 | 决定「叫不叫得上可部署教学软件」 | 品类核心承诺不成立 |
| L2 任务阻断 | 核心任务走不通 | 任务成功条件缺前提 |
| L3 健壮性 | 静默失败 / 恢复不了 | 失效不可见 |
| L4 体验 | 可用但别扭 | 有绕行路径 |
| L5 工程债 | 用户不可见，拖慢演进 | 返工率 / 不可测 |

域划分：G-RUN 运行可用性 / G-LRN 教学能力 / G-DIST 分发与版本 / G-A11Y 可访问性 / G-ENG 工程质量。

## 5. 演进路线（版本映射）

### 5.1 路线总览

| 阶段 | 版本 | 主题 | 关闭的 Gap | 出口标准 |

### 5.2 E0 · v0.11 稳定性与可测性收口

入口条件：无（可立即启动）。

| 项 | 内容（方案详见规划 §9）| 关闭验收（破坏性）|
|---|---|---|
| G-RUN-1 | Web 版 vendor 化，复用 desktop/build-app.mjs 逻辑 | hosts 屏蔽 cdn.jsdelivr.net 后加载线上包，3D 与全部知识功能照常；若保留 CDN 模式，断网 8 秒内出现双语失败提示与桌面版链接，绝不白屏 |

## 6. 依赖与风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **vendor 化使仓库体积增加约 1.3MB** | git 与部署体积上升 | Three.js 单文件可接受；不引入打包器保持 C-1/C-3；若未来资产增多再评估 LFS |
| **跨条目联动：E0 未完成就重打桌面包** | 把 CDN 缺陷之外的已知问题固化进离线分发，用户拿到即过时 | 路线强制 E1 入口条件 = E0 出口达成 |
| **跨条目联动：无 CI 时新增契约校验脚本仍靠人跑** | G-ENG-2 形同虚设 | E0 交付脚本、E1 立即接入 CI，两阶段绑定 |
| 桌面包每次重打约 435MB 上传 | 发布耗时长、易被连接重置中断 | 沿用 --partial 续传 + 服务器 sha256 回读（规格 §8.2 已固化）|
| 内容更新与代码耦合（C-1 内容即代码）| 非技术人员无法更新教学内容 | 显式非目标（规划 §12）；靠契约校验保证改动安全 |
| Safari/Firefox 未系统验证 | 潜在兼容问题在教室现场暴露 | E0 的启动自检至少保证「不可用时说人话」；E2 补一轮跨浏览器实测 |
